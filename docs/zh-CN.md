# shebanglf 中文说明

一句话用途：一条本地命令，把 Git 跟踪的 UTF-8 shebang 脚本中的 CRLF 换行改成 LF，修复 Linux、macOS、WSL 中由此引起的脚本启动失败。

## 为什么做它

脚本明明存在，却报 `/bin/bash^M: bad interpreter`，原因可能是 Windows 风格换行把 `\r` 留在了解释器名称后面。只修改文件名带 `.sh` 的脚本会漏掉 `bootstrap`、`gradlew` 等启动器；转换整个仓库，又可能误改 Windows 批处理文件或测试夹具。

本工具用 Git 索引选文件，再检查文件开头是否为 `#!`。它只转换这样的脚本，不执行待处理脚本。公开证据、最多两个候选的比较，以及现有工具的版本和成本，见 [problem.md](problem.md)。三名报告者各算一人，没有用同一人的补充评论凑数。

## 安装

需要 Python 3.9+ 和 `PATH` 中可用的 Git，没有 Python 第三方依赖，不需要账号、联网或服务端 API。支持目标为 Linux、macOS 和 WSL 内的 Linux；实际仅验证了 Linux、Python 3.14.4、Git 2.53.0，未验证 macOS 和其他版本。原生 Windows 不支持。

`shebanglf.py` 一个文件就是完整工具，可以直接运行。若希望在本项目内装成命令，在项目目录执行：

```sh
mkdir -p bin
cp shebanglf.py bin/shebanglf
chmod +x bin/shebanglf
./bin/shebanglf --help
```

不必更改系统目录、全局配置或 `PATH`。

## 最小示例

假设目标仓库中已加入 Git 索引的 `bootstrap` 内容是 `#!/bin/sh\r\necho hello\r\n`：

```sh
# 只检查：不写文件，发现问题返回 1。
python3 shebanglf.py /path/to/repo

# 修复：这就是解决问题所需的一条命令。
python3 shebanglf.py --fix /path/to/repo
```

修复输出示例：

```text
FIXED "bootstrap": 2 CRLF line endings
scripts=1 affected=1 fixed=1 skipped=0 errors=0
```

省略路径时使用当前 Git 工作区；传入仓库子目录也会检查整个仓库。文件必须已经加入索引，但仓库不必有提交。工具只改工作区，不自动 `git add`；可以用 `git -C /path/to/repo diff` 检查结果。

退出码 `0` 表示支持范围内没有 CRLF 或修复成功，`1` 表示检查发现 CRLF，`2` 表示参数、Git 或文件处理错误。遇到单个文件错误会继续处理其他文件，因此退出 `2` 时可能已有部分文件修复成功。跳过的文件不代表通过验证。

## 实现与保护

Git 文件清单使用 NUL 分隔，调用命令不经过 shell，所以包含空格、换行或命令替换字符的文件名不会变成命令。输出用 JSON 字符串转义路径。

修复时先在同目录写临时文件，完成写入、权限设置和同步后，再替换原文件。普通写入失败不会留下半截原文件。保留属主、属组和权限位，不增加可执行权限；干净文件不写回。索引中的符号链接和子模块会报告跳过；工作区里的链接替换、合并冲突、缺失文件和不安全候选会报告错误。

## 明确限制

- 只处理 Git 索引中的文件，且文件必须以精确的 `#!` 字节开头。未跟踪文件、BOM、没有 shebang 的 shell 文件、子模块内容不处理。稀疏检出缺少索引文件时会报告错误。
- 脚本必须为 UTF-8；除制表、CR、LF 外的 ASCII 控制字符视为不适合自动处理。非 UTF-8 和疑似二进制脚本会报错，不猜编码。
- 整个脚本中的 CRLF 都会转换，包括字符串和 heredoc 中的 CRLF。孤立 CR 不变，不补最后一个换行，不检查解释器和语法。如果嵌入内容故意需要 CRLF，先用检查模式评估。
- 有 CRLF 的硬链接和不可写文件拒绝修复。替换会改变 inode 和修改时间，不保留 ACL、扩展属性；没有跨文件事务、备份或回滚。强行终止进程可能留下临时文件。
- 仅适合可信、没有并发修改的工作区，不能防御扫描期间的路径替换。会完整读取每个跟踪的普通文件，大型资源可能占用较多内存。
- 不修改 Git 属性或配置，也不能防止下一次检出再次带入 CRLF。长期预防应另行设置合适的 `text eol=lf` 属性。工具忽略全局/系统 Git 配置和继承的 `GIT_*` 环境覆盖，仍使用仓库本地配置。

## 测试与自评

用普通用户在项目目录运行：

```sh
python3 -B -m unittest discover -s tests -v
```

真实结果为 17 项测试通过，耗时 1.673 秒，完整输出在 [test-results.txt](test-results.txt)。测试调用真实 CLI 和 Git，所有临时仓库都在本项目的 `.test-tmp/` 内。覆盖正常修复、无扩展名脚本、修复后执行、索引和权限保持、重复运行、异常文件名、链接、子模块、冲突、编码、权限和写入失败。逐条失败再通过的原始记录和对应关系见 [tdd.md](tdd.md)。

自评：值得作为小型源码工具公开，价值是省去一次容易遗漏无扩展名脚本的筛选操作。它没有发明换行转换；已知单文件时 dos2unix 更直接，已有合适 pre-commit 配置的团队也可能不需要它。没有进行发布操作，是否公开由林峰决定。
